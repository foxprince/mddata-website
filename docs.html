Market Trading Hours API

Get standard trading hours, call auction and after-hours information for major markets. The interface follows REST specifications and is compatible with MDdata full authentication process.

Endpoint

GET https://api.mddata.cc/v1/market/trading-hours

Headers

  • Authorization: Bearer <token>
  • Accept: application/json

Query

  • market — Exchange code, such as SSE、HKEX
  • date — Optional, ISO date. Defaults to the latest trading day.

Response Example

Main fields cover commonly used continuous auction, lunch break and after-hours trading information. 

{
  "market": "SSE",
  "date": "2025-09-23",
  "timezone": "Asia/Shanghai",
  "sessions": [
    {
      "type": "pre_open",
      "start": "09:15",
      "end": "09:25"
    },
    {
      "type": "continuous",
      "start": "09:30",
      "end": "11:30"
    },
    {
      "type": "continuous",
      "start": "13:00",
      "end": "15:00"
    }
  ],
  "remarks": "Monday to Friday, excluding holidays."
}

Error Codes

Status Code Description Solution
401 Authentication failed or Token expired Refresh Token or contact administrator to reset key
404 Exchange code does not exist Check if the market parameter complies with MDdata standards
429 Request frequency exceeds limit Reduce call frequency or upgrade plan to get higher quota

Authentication Workflow

Each request uses short-lived access tokens issued by the MDdata identity gateway. Submit your `client_id`, nonce and HMAC signature to `/v1/auth/token` and rotate the refresh token every 24 hours. Never embed secrets in client-side applications; use a vaulted service to proxy requests when building web experiences. 

{
  "clientId": "md_xxxxx",
  "nonce": "1700000012",
  "signature": "hex(hmac_sha256(secret, payload))"
}

Authentication checks include IP allowlists, token expiry, MFA status and scope validation. Failures return 401 with an error payload describing the rejected stage so operations teams can react quickly.

Rate Limits & Throughput

Default quotas serve 600 REST calls per minute per tenant. WebSocket connections are limited to 5 concurrent channels for sandbox tenants and 20 for production. Submit a request via the MDdata console to raise limits for large-scale backfills or live trading desks.

Limit Type Threshold Recommended Backoff
REST Requests 600 rpm Exponential backoff starting at 200 ms
WebSocket Streams 5 channels (sandbox) Reconnect with jitter after 3 s
Historical Downloads 20 GB per hour Queue jobs via `/v1/jobs` and poll status

WebSocket Streaming Lifecycle

Persistent streams deliver order book deltas with microsecond timestamps. Respond to heartbeat frames every 15 seconds to keep connections alive. Upon reconnect, send the last confirmed sequence number so the gateway can replay missed deltas. 

{
  "action": "subscribe",
  "channel": "quotes",
  "symbols": ["SSE:600519", "HKEX:00700"],
  "seq": 1854309
}

Messages tagged with event = "snapshot" replace your local order book. Apply event = "delta" updates sequentially, discarding out-of-order frames. The replay buffer persists 2 hours of data for seamless gap recovery.

SDK Integration Tips

  • Use the official Python SDK batching helpers to aggregate symbols into one request.
  • Enable HTTP/2 in the TypeScript client to reduce TLS negotiation during bursts.
  • Configure Go client pools with connection reuse to sustain 10k rpm workloads.
  • Leverage Java interceptors to refresh tokens 2 minutes before expiry.

Compliance & Audit Logging

MDdata retains signed access logs for 365 days. Enterprise tenants can schedule daily exports to encrypted object storage. Enable field-level masking to keep PII hidden in payloads and filter the audit API by user, IP address or endpoint when preparing regulatory reports.

Quick Start

  1. Submit a sandbox application through the MDdata Console.
  2. Create service credentials and exchange them for an access token via `/v1/auth/token`.
  3. Call `/v1/market/trading-hours` with your desired `market` and optional `date` parameter.
  4. Sync returned sessions into your trading calendar or risk control pipeline.
